# Work in projects

{% hint style="success" %}
**New: brand context from the web.** DS-1 can now search the web for any brand and load what it finds straight into your project: what the brand sells, how it talks, its latest news, and its competitors. Every chat in the project starts from that context. [Jump to Step 4](#step-4-add-brand-context-from-the-web).
{% endhint %}

## What a project is

A project is a dedicated workspace inside DS-1. Everything you do in it stays in it: the files you upload, the audiences you build, the chat history. Nothing carries over into your main DS-1 session, and nothing from main DS-1 comes in.

That siloing is the point. One project per client, campaign, or pitch means you can open it three weeks later and DS-1 still has the context: the brief you uploaded, the segments you shortlisted, the insights you attached. You can also share a project with specific teammates, so the context travels with the work instead of living in one person's session.

## Why use one

* **Brand context on demand.** Search the web for the brand you're working on and bring its products, messaging, recent news, and competitors into the project in about two minutes.
* **Context that persists.** Upload a brief once and every agent in the project can read it. No re-explaining the campaign each session.
* **Clean separation.** Client A's files never surface while you're working on Client B.
* **Shared ground.** Invite the teammates on the account and they see the same files, audiences, and history you do.
* **Full DS-1 inside.** Projects are not a reduced mode. Everything you can do in main DS-1, including finding prebuilt audiences and building custom ones, works the same way in a project.

## Walk through a project

### Step 1. Open Projects

Click **Projects** in the left sidebar of DS-1.

<figure><img src="../.gitbook/assets/projects-01-sidebar.png" alt="The DS-1 left sidebar with Projects circled"><figcaption></figcaption></figure>

The Projects page splits into three tabs: **Your projects** for the ones you own, **Team** for your organization's, and **Shared with you** for projects a teammate added you to. Search by name, or sort by **Last updated** to get back to what you had open yesterday.

<figure><img src="../.gitbook/assets/projects-01b-projects-list.png" alt="The Projects page with search, a Last updated sort, and Your projects, Team, and Shared with you tabs"><figcaption></figcaption></figure>

### Step 2. Create a project

The **New project** dialog asks for three things:

* **Project name.** Name it for the work it holds: the client, the campaign, or the pitch. A clear name is what makes the project findable later, so prefer *SafeGuard Q3 Auto Campaign* over *new project*.
* **Description.** One line on what the project is for. Worth filling in when you're sharing with a team.
* **Project knowledge.** Attach context up front with **Upload files** or pull straight from **Drive**. You can also add files later, so don't wait on this to create the project.

<figure><img src="../.gitbook/assets/projects-02-create.png" alt="The New project dialog with fields for project name, description, and project knowledge"><figcaption></figcaption></figure>

Click **Create project** and it opens, ready to work in.

### Step 3. Add your context

Whether you attached files at creation or not, you can keep building a project's knowledge as the work develops. The project panel holds four kinds of context, each with a **+** to add more:

* **Instructions.** Standing direction on tone and perspective, so you don't restate it every session. For example *use a more formal tone* or *respond as the marketing team for Brand X*.
* **Files.** Briefs and RFPs for DS-1 to analyze and turn into an audience strategy.
* **Audiences.** Your own segment lists or audience taxonomy, so recommendations can point at what you already license.
* **Existing insights.** Insights you've already run in DS-1, attached as project knowledge rather than rebuilt.
* **Brand context.** A web search on the brand, covered in the next step.

<figure><img src="../.gitbook/assets/projects-03-panel.png" alt="A project's panel showing Instructions, Files, Audiences, and Add existing insights"><figcaption></figcaption></figure>

Anything in the panel is available to every agent you run in the project. The project chip sits in the composer, so DS-1 reads the file rather than asking you to retype the campaign each session. Ask for a rundown and you get the brief's goal, objectives, target audiences, geography, budget, and media mix back as a summary you can work from.

<figure><img src="../.gitbook/assets/projects-03-files.png" alt="DS-1 reading an attached project file and summarizing the brief, with the project chip in the composer"><figcaption></figcaption></figure>

### Step 4. Add brand context from the web

When the project is for a specific brand, you need a baseline before you can plan: what it sells, what it costs, what it's saying right now, and who it competes with. DS-1 now does that research for you. It searches the web, pulls together what it finds, and saves it to the project as context that every chat can draw on.

**Start the search.** Open the **Brand context** card in the project panel and click **Search the web**.

<figure><img src="../.gitbook/assets/projects-04a-brand-context-card.png" alt="The empty Brand context card with a Search the web button"><figcaption></figcaption></figure>

You can also start it from the composer: click **+** and pick **Web search**.

<figure><img src="../.gitbook/assets/projects-04b-web-search-menu.png" alt="The composer's add menu with Files, Insights, and Web search"><figcaption></figcaption></figure>

**Let it research.** Enter the brand name and DS-1 runs a series of searches across pricing, financial results, and the latest campaigns and news, listing each one as it goes. It takes a minute or two. You can close the window; the search keeps going.

<figure><img src="../.gitbook/assets/projects-04c-searching.png" alt="The Brand context window searching the web for acne studios, listing the searches it has run"><figcaption></figcaption></figure>

**Choose what comes in.** The results come back as sections you can select or deselect, so only what's useful lands in the project. That includes **Competitors**: brands in the same space, each tagged by price position (*Similar price*, *Cheaper*) with their latest moves and a date. Competitors are a useful starting point when you're deciding who else this audience shops with. When it looks right, click **Add to project**.

<figure><img src="../.gitbook/assets/projects-04d-competitors.png" alt="The Competitors section with Toteme and Ganni cards, price tags, and recent news, above the Add to project button"><figcaption></figcaption></figure>

**Read what was saved.** The Brand context card now holds the research: dated recent developments with key figures highlighted, a **Watch out** section flagging conflicting sources and claims to avoid, and chips for the competitors. Use **Check for updates** any time to rerun the search for the latest, or **Remove** to clear it.

<figure><img src="../.gitbook/assets/projects-04e-saved-context.png" alt="The saved Brand context card with Recent and Watch out sections, competitor chips, and Check for updates"><figcaption></figcaption></figure>

**Put it to work.** Ask in plain English. Inside a project, DS-1 answers from the project's own context. Here it proposes an age range from the brand's price points and positioning, framed as a hypothesis to test.

<figure><img src="../.gitbook/assets/projects-04f-chat.png" alt="DS-1 answering a question about target age range using the project's brand research"><figcaption></figcaption></figure>

{% hint style="info" %}
Brand context is a starting point, not a source of truth. Read the **Watch out** notes before you quote a figure or a claim to a client.
{% endhint %}

### Step 5. Share with your team

Open **Share** and search your organization by name or email. Anyone you add can use the project's chats, files, and audiences, and it shows up under their **Shared with you** tab. You set the level when you invite, so a reviewer can be **Can view** while a collaborator gets edit access.

<figure><img src="../.gitbook/assets/projects-04-share.png" alt="The Share dialog with a name search, an access dropdown, the project owner, and an org-wide access row"><figcaption></figcaption></figure>

### Step 6. Build from the brief

Work exactly as you would in main DS-1, except the agents draw on the project's context instead of a prompt. Ask for product recommendations against the brief and DS-1 assembles an audience brief on the canvas, spanning the full product set: your own audiences, Custom AI, Custom Search Lookalikes, Predictive Contextual, Custom URL audiences, and prebuilt audiences.

<figure><img src="../.gitbook/assets/projects-05-agent-run.png" alt="DS-1 recommending a full audience brief from the attached brief, with search-term seeded audiences on the canvas"><figcaption></figcaption></figure>

Review the canvas before committing. Reorder, edit, or remove sections, and on seeded audiences add or drop individual search terms. When it looks right, say **build them all** and DS-1 builds and syndicates the set to your destination platform, reporting back which segments went out and which are still building. Everything it produces stays filed under the project.

{% hint style="info" %}
New to the audience agents? Start with [Find prebuilt audiences](agents/find-prebuilt-audiences.md), then run the same flow inside a project.
{% endhint %}

### Step 7. Map your own taxonomy

Upload your custom audience taxonomy and DS-1 adds a **Your Audiences** section to the brief: the segments from your own taxonomy that best fit the campaign objective, pulled out of a list that is usually far too long to hand-search. Here it surfaced the Epsilon nodes that match an amusement park campaign, across both transactional purchaser paths and lifestyle interest paths.

<figure><img src="../.gitbook/assets/projects-06-your-audiences.png" alt="A Your Audiences section listing Epsilon taxonomy paths matched to the campaign objective"><figcaption></figcaption></figure>

Use **Copy** to lift the full taxonomy paths straight into your DSP or planning doc.

{% hint style="warning" %}
These are client-provided planning references, not Dstillery segments. DS-1 matches them to the objective so you know what to activate on your side, but it does not build or syndicate them.
{% endhint %}

### Step 8. Pick the work back up

Every project keeps its own record, split in two:

* **Your chats** houses all the chats kicked off by you and by anyone who has shared the project with you, each with its opening question, who ran it, message count, and date. Click one to reopen the thread where you left it. Chats are private until shared, and a teammate's shared thread opens **read-only**, so you can follow their reasoning without changing it.
* **Activity** is the change log for the project itself: who updated the instructions, who added a file, and when. On a shared project it's how you catch up on what teammates changed since you were last in.

<figure><img src="../.gitbook/assets/projects-07-history.png" alt="The Your chats tab listing project sessions with who ran them, message counts, and dates"><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/projects-07b-activity.png" alt="The Activity tab listing instruction updates and file additions with names and dates"><figcaption></figcaption></figure>

Because the record is per project, a client's history stays with that client. Reopening a thread from three weeks ago is how you revisit a segment mid-flight or rebuild a shortlist for the next flight without starting the brief over.

### Step 9. Pull an existing chat into a project

Work that started outside a project doesn't have to stay there. Open **History** in the left sidebar for every past conversation with DS-1, find the one you want, and use **Assign to project** to file it under any project you have.

<figure><img src="../.gitbook/assets/projects-08-assign-chat.png" alt="The History page with the Assign to project menu open on a conversation, listing available projects"><figcaption></figcaption></figure>

{% hint style="info" %}
Assigned conversations join the project's context and record. Useful when something you explored ad hoc in main DS-1 turns out to belong with the account.
{% endhint %}
